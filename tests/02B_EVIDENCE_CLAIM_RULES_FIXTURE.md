## 1. Purpose

This fixture validates whether the Frozen evidence-based journalism model can be implemented through deterministic authored Evidence–Claim rules without extending Claim Atom semantics or giving the LLM evidence/truth authority.

The required boundary remains:

> AI controls language. Deterministic game systems control reality.

No Reputation/Public Opinion/Threat/Money consequences, Dify workflow, Unity implementation, backend persistence technology, production prompt, truth score, misinformation score, bias score, or generic sentiment system is defined here.

## 3. Evidence–Claim Relationship layer

02B proposes a separate authored deterministic relationship layer:

```text
Evidence Registry
+
Semantic Proposition Registry
+
Source Registry
↓
Authored Evidence–Claim Relationship Table
↓
Deterministic Publication Evaluator
```

The relationship table is not part of Claim Atom and is never generated by the LLM.

Conceptual relationship record:

```text
relationship_id
evidence_id
dimension            # ATTRIBUTION | UNDERLYING
target_id
value_id
polarity
source_ref_id?       # ATTRIBUTION only
source_expression_commitment_mode?  # optional ATTRIBUTION metadata
effect               # SUPPORTS | CONTRADICTS
qualifies_for_modes[]
```

`qualifies_for_modes[]` is authored deterministic policy, not model confidence or a score.

An attribution relationship never automatically becomes an underlying-proposition relationship.

## 5. Publication-time snapshot

Publication evaluation must not read the player's current/latest state. A deterministic publication-time snapshot is frozen when publication is evaluated.

Minimum conceptual snapshot:

```text
publication_id
publication_sequence_or_deterministic_timestamp
original_headline_text
validated_claim_set

evidence_access_snapshot[]
  evidence_id
  known_to_player
  content_accessible_to_player
  possessed?                    # only if possession exists in gameplay
  deterministic_eligibility_state

visible_source_ref_ids[]
evidence_claim_ruleset_version
publication_evaluator_version
```

Stored evaluation record should retain:

```text
claim_evaluation_results[]
supporting_evidence_ids[]
contradicting_evidence_ids[]
excluded_evidence_ids[]
exclusion_reason
evaluation_reason
```

Minimum evidence eligibility:

```text
known_to_player
AND content_accessible_to_player
AND deterministically_eligible
```

World existence, ownership, player knowledge, content access, evidentiary eligibility, and canonical truth remain distinct concepts.

## 6. Deterministic evaluation pipeline

```text
Player Headline
↓
LLM Claim Extraction
↓
Validated Claim Set
↓
====================
AI AUTHORITY ENDS
====================
↓
Freeze Publication-Time Snapshot
↓
For each Claim Atom
↓
Validate source visibility
↓
Select publication-eligible evidence
↓
Evaluate ATTRIBUTION relationships
↓
Evaluate UNDERLYING relationships
↓
Apply deterministic commitment-mode rule
↓
Store immutable evaluation + evidence basis
```

Canonical reality is a separate deterministic path and must not be used to produce the evidence-support result.

## 7. Attribution-support rules

For a Claim Atom with `source_ref_id`:

1. The source must be authored and player-visible at publication time.
2. Attribution evidence must explicitly match the source plus target/value/polarity and any consequential authored source-expression modality.
3. Underlying truth cannot rescue unsupported attribution.
4. Attribution support grants no source reliability, honesty, accuracy, or underlying truth authority.

An unavailable or nonexistent source ID is a semantic/contract validation failure and does not become `EVIDENCE_INSUFFICIENT`.

## 8. Underlying-proposition-support rules

Underlying evaluation ignores `source_ref_id` and independently matches authored relationships for:

- `target_id`;
- `value_id`;
- `polarity`;
- qualifying commitment mode.

Evidence that proves a source said X does not automatically support X. Underlying support exists only when an explicit authored UNDERLYING relationship exists.

No cross-value contradiction is inferred unless the authored relationship explicitly encodes it. For example, evidence supporting Company A funding does not automatically contradict Mayor Office funding unless the evidence relationship says the possibilities are mutually exclusive in that context.

## 9. Canonical-reality separation

The fixture must allow both:

```text
canonically true
+
publication-time unsupported
```

and:

```text
publication-time supported
+
canonically false
```

Canonical truth does not determine publication support. Publication support does not rewrite canon.

## 10. Validation-local evaluation states

The following are deterministic publication-evaluation labels only; they are not semantic statuses and do not change the Frozen `RESOLVED / AMBIGUOUS / UNSUPPORTED` taxonomy:

- `SUPPORTED`
- `CONTRADICTED`
- `INSUFFICIENT`
- `NOT_APPLICABLE` — attribution axis only when no source is attributed

Audit reasons may include:

- `NO_RELEVANT_EVIDENCE`
- `BELOW_MODE_REQUIREMENT`
- `CONFLICTING_EVIDENCE`
- `CONTESTED_BASIS`

Validation rule used by this fixture:

### ASSERTED

- support only → `SUPPORTED`
- contradiction only → `CONTRADICTED`
- support + contradiction → `INSUFFICIENT / CONFLICTING_EVIDENCE`
- neither → `INSUFFICIENT`

### SPECULATIVE / QUESTIONED

- support only → `SUPPORTED`
- contradiction only → `CONTRADICTED`
- support + contradiction → `SUPPORTED / CONTESTED_BASIS`
- neither → `INSUFFICIENT`

For QUESTIONED, `SUPPORTED` means there is authored evidence basis for raising the proposition as a question; it is not a truth answer.

## 11. Representative cases

### B01 — Direct supported assertion

`Militia fired first.` with accessible `EV_VIDEO_A`:

- underlying = `SUPPORTED`
- basis = `EV_VIDEO_A`
- canonical reality also says MILITIA, but canon was not used to derive support.

### B02 — Direct contradicted assertion

`Security forces fired first.` with accessible `EV_VIDEO_A` and unavailable `EV_AUDIO_A`:

- underlying = `CONTRADICTED`
- basis = `EV_VIDEO_A`.

### B03 — No relevant evidence

`Mayor's office funded the operation.` with only unrelated fire evidence:

- underlying = `INSUFFICIENT / NO_RELEVANT_EVIDENCE`.

### B04 — Attribution supported, underlying contested

`Witness A says security forces fired first.` with accessible `EV_AUDIO_A`, `EV_VIDEO_A`, and visible `SRC_WITNESS_A`:

- attribution = `SUPPORTED` via `R-A01`;
- underlying has support via `R-U01` and contradiction via `R-U02`;
- because the claim is ASSERTED, underlying = `INSUFFICIENT / CONFLICTING_EVIDENCE`.

### B05 — Both attribution and underlying support at publication time

Same headline, but `EV_VIDEO_A` not yet accessible:

- attribution = `SUPPORTED`;
- underlying = `SUPPORTED` via independent relationship;
- canonical reality still remains MILITIA and is not rewritten.

### B06 — Canonically true but publication-time unsupported

`Company A funded the operation.` before `EV_LEDGER_A` is known/accessed:

- underlying = `INSUFFICIENT`;
- canonical = COMPANY_A.

Later discovering the ledger does not rewrite the old publication evaluation.

### B07 — Publication-time supported but canonically false

`Security forces fired first.` with accessible `EV_AUDIO_A` but not `EV_VIDEO_A`:

- underlying = `SUPPORTED` by validation-only `R-U01`;
- canonical reality = MILITIA.

This is valid under the Frozen journalism model.

### B08 — Multi-claim headline

`Security forces fired first, and Company A funded the operation.` with accessible `EV_VIDEO_A` and `EV_LEDGER_A`:

- fire-first Claim Atom = `CONTRADICTED`;
- funding Claim Atom = `SUPPORTED`.

Each Claim Atom is evaluated independently; no whole-headline average or misinformation score is introduced.

### B09 — SPECULATIVE / QUESTIONED under conflict

With `EV_AUDIO_A` and `EV_VIDEO_A` both accessible:

- `Security forces may have fired first.` → `SUPPORTED / CONTESTED_BASIS`;
- `Did security forces fire first?` → `SUPPORTED / CONTESTED_BASIS`.

### B10 — Later evidence

Publication 001 freezes `EV_AUDIO_A` only and evaluates `Security forces fired first.` as supported under the fixture. Later discovery of `EV_VIDEO_A` may support a new present-day assessment, but Publication 001 remains immutable.

### B11 — Evidence exists but player cannot access it

If `EV_VIDEO_A` exists in the world but is not known/content-accessible to the player, `Militia fired first.` remains `INSUFFICIENT` at publication time despite canonical truth and world evidence existence.

## 12. Multi-evidence rules

- no majority voting;
- no LLM comparison of which evidence seems stronger;
- no hidden numerical truth/evidence score;
- duplicate evidence IDs count once;
- qualification by commitment mode is authored;
- evidence conflict remains explicit;
- relationship rows, not model inference, determine support/contradiction.

## 13. Auditability requirements

Given:

```text
Validated Claim Set
+ Publication Snapshot
+ Evidence–Claim Ruleset version
+ Publication Evaluator version
```

the game must reproduce the same publication result without any LLM call, current inventory, current knowledge, current source visibility, or conversation memory.

The audit record must answer what the player published, which Claim Atoms were validated, what evidence was available then, which evidence was excluded and why, which relationship rows matched, what supported/contradicted each claim, and which ruleset/evaluator version produced the result.

A later re-evaluation creates a new assessment; it never mutates the original publication evaluation.
