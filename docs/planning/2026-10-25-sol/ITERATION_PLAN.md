## 1. 产品判断：让玩家为一句话负责

玩家幻想是：在截稿压力下，成为能主动追问、选择调查方向、决定如何表达并承担后果的记者。核心乐趣来自“我愿意以怎样的依据，写到什么程度”，而不是找出系统预藏的唯一正确标题。

现有货场故事已经有三个有效的设计支点：目击者的说法与录像可以相互冲突；查开火顺序和查资金不能同时完成；标题的归属方式改变报道责任。优先把这三个支点做得可读、可比较、可回想，随后才增加内容长度。不能靠更长的 NPC 闲聊把五分钟内容填成二十五分钟。

功能开发有明确停点。D18 单例成功不能推导中文采访已可靠，更不能让合法候选直接执行玩家没表达的意思。现有实现已让**玩家看见并确认“系统准备执行什么”**；四句脚本只证明操作路径。确认是表达控制工具，不能成为把理解质量责任全部交给玩家的理由；玩家点击同意也不把候选变成 fidelity PASS。这既是操作权，也是游戏中的记者笔记，不应呈现成调试面板。

### 当前复盘：先让一句话与一个决定有分量

**当前短篇最值得保留的体验，是调查取舍改变手上的材料，再由玩家决定报道怎样表述。** 采访确认负责保护这一体验中的表达权；它本身不是需要反复完成的审表小游戏。I1–I2 当前目标收敛为：玩家知道自己准备说什么、什么时候才发生行动，以及后续选择依据来自哪里。20–30 分钟、更多追问和真实生成继续保留为后续目标，不拿时长或按钮数量评价这一轮。

复盘直接依据 [脚本与确认控制](../../../ai/prototype/interview_flow.py)、[现有界面](../../../ai/prototype/story_desktop.py)、[作者短篇](../../../tests/fixtures/railyard_story.experimental.v0.1.json)及[已保存的确认画面](verification/i1-i2/review-all-tactics.png)。以下不声称已观察到玩家困惑。

| 现有事实 | 游戏设计判断 / 待验证风险 | 对当前计划的处理 |
| --- | --- | --- |
| 三条可执行示例都询问谁先开火；含糊示例不执行。脚本外的正常改写也不执行 | 大输入框和“返回改写”可能让人期待能自由修好一句话；目前恢复路径主要是载入已有示例 | 脚本阶段只验收表达复核与草稿保护，不宣称已经实现自由表达的纠错闭环。继续保留明确示例说明；先观察是否读懂，不为本轮增加解析器 |
| 施压和复合语气都取得同一录音、走同一 pressure 分支；后者完整展示三策略 | 语义完整性与策略深度是两回事；目前施压有风险和拒绝继续合作的作者回应，却没有额外信息收益 | 保留为表达后果示例，不宣传三种独立战术，也不为“平衡”临时奖励威胁。是否需要不同回应/收益属于以后作者设计，当前冻结 |
| 确认卡保留原句、全部含义、返回和执行；截图中三策略已形成较长阅读面 | 玩家可能把确认当机械继续，或只读醒目的执行按钮；增加更多解释也可能加重负担 | 优先维持“原句 → 关键含义 → 两个动作”的阅读顺序。不得为压缩版面隐藏策略；是否调整间距/重复提示须由具体读不清处支持，不重绘整个 UI |
| 采访采用与公开刊发分开；NPC 会问“你们会把我的话登出来吗”，确认卡说明没有刊发承诺 | 记录、采信和刊发容易被混为一谈；当前并没有自由承诺机制 | 复核应解释玩家即将做的采访行动，不暗示 NPC 同意、内容真实或一定刊发。保留角色原话与系统说明的视觉区分 |
| 录像核查开火顺序，账簿改查资金；都占唯一追加调查机会，账簿另花 500 | 这是报道方向的取舍；钱目前没有后续消费，不能宣称已有完整经济压力。两个路线都获得同类数值奖励也不代表趣味等价 | 观察玩家能否说出自己放弃核查了什么，不要求两条路线奖励对称；不增加倒计时、钱的去处或第三路线来制造深度 |
| 结局显示整段会话的变量差值；压力事件加风险，争议归属刊发事件本身没有变量变化 | 在最后一屏看到风险 +1，可能误以为引用目击者受到了惩罚；原句到后果的因果容易被总数遮住 | 把“后果来自哪次选择”列为现有体验的优先核对项。若以后出现误解，先在既有反馈位置澄清作者因果，不改奖励表、不建新结局/回放系统 |
| 录音说明“说过不等于真实”，但单录音临时支持规则仍可给直接断言支持结果 | 作品可能传达相互拉扯的教学信号；这是实验政策限制，不是文字润色能消除的问题 | 现版仍是实验规则；新样章已按DEC-023选定本案关系，独立版本制作，不能覆盖旧fixture或把旧试玩解释成新政策 |

当前美术方向继续沿用纸张、墨色、暗红和货场剪影。它已能给阅读提供情境，暂不增加装饰、动效或角色资产。优先级依次为：**理解当前行动与后果 → 找得到返回和材料 → 阅读密度与焦点 → 视觉装饰**。这是设计排序，不是新增开发任务。

### 玩家应该分清的四件事

| 时点 | 玩家需要知道什么 | 现有状态边界 / 设计约束 |
| --- | --- | --- |
| 起草、查看理解、返回改写 | 这还是我准备说的话；系统没有替我采访 | 草稿/候选可丢弃；无证据、资金、调查或分支变化。脚本不支持不等于玩家问错 |
| 明确确认采访 | 我授权采用这次采访及其已展示的表达方式 | 原作者规则执行，才取得录音或施压后果；不是承诺刊发。确认不证明说法为真 |
| 翻证据 / 选调查 / 接受交易 | 读已有材料不花机会；选方向才用掉机会；付款是另一项明确承诺 | 不给翻页加确认，不为每个选择叠确认框；调查取舍在选项前讲清，报价与付款分开 |
| 选标题 / 签发 / 看结局 | 选稿仍可改；签发才冻结这一版；后果包含此前已经做过的选择 | 材料在手不等于全知真相；结局解释责任，不能把变量总数包装成记者道德评分 |

### 规划完成与体验完成分别记录

上一轮设计复盘的完成条件是：已有事实可追溯、风险与事实分开、I1–I2 未完项可判定、未来工作不被误读为执行指令。该轮已按文档范围完成；最新案件设计的完成边界见第 11 节，不受“只修最小一处”的旧排序约束。

未来若继续验证同一短篇，任务 05 与 10 的体验部分共用一次首次读者观察，不为两个标签让同一人重走同一路线。先让读者自行操作，结束后请其用自己的话说明“哪一步才采访了”“为什么放弃另一项调查”“标题在转述谁的话”“结果源于哪次选择”；记录具体操作、原话及主持人是否提示。愿意承担施压/刊发风险不算操作失败，耗时也不能单独说明困惑。人数仍沿原 05 的两位建议，不声称统计代表性。

**当前四条脚本没有故意漏策略的确认卡。** 因而现版可以观察复核、返回和阶段理解，却不能完成“发现系统遗漏”的判据。任务 10 的遗漏识别保留为未来独立研究问题；本轮不创建错误候选或研究资产，也不把改写成功一次等同于检测出理解错误。将来如安排该研究，应与正式试玩分开说明其故障情境，并分别记录无提示发现、提示后发现、未发现；不会因玩家未发现而宣称系统已安全。

旧样机观察仍应区分表达与操作问题；01 的目标窗口适配、中文 IME、辅助技术各有未测边界，不能用普通鼠标走查替代。新的案件玩法按第 11 节整体设计，不受上一轮“只修最小一处”的排序限制，也不为了关闭旧任务机械添加控件。

## 2. 核心决策怎样落在玩家手上

| --- | --- | --- | --- | --- |
| 0–2 分钟 | 进入货场任务：不确定但有方向 | 读简报，知道今晚要刊发、只能追加一项调查 | 现有 premise，改为不预告未取得录像内容的玩家简报 | 一屏、一项首要动作；说明可随时翻证据册 |
| 2–7 分钟 | 第一次采访：建立自己的说法 | 两到三个作者可响应的追问，自由写一句，确认执行含义 | 目击者现有知识边界；追问内容是待编写提案 | 两轮必要互动即可继续，不以字数锁进度 |
| 7–9 分钟 | 取舍：线索不够而时间有限 | 比较录像线 / 资金线，作唯一追加调查选择 | 现有 followup 节点 | 在离开前说明互斥，不展示放弃线的答案 |
| 9–14 分钟 | 验证或交易：获得新材料 | 录像线：逐条核对观察；资金线：请求、报价、确认 / 拒绝 | 三份现有证据与账房边界；细节展示待作者补写 | 两条路线相近时长；拒绝交易也能顺利回桌 |
| 14–18 分钟 | 证据册：我的判断与来源是否相符 | 并排读两份已取得材料，标记准备引用的片段 | 可见证据，不引入新可靠性公式 | 手动比较，不自动“揭穿”；单份材料也能继续 |
| 18–22 分钟 | 编辑台：从材料变成一句话 | 自由标题、查看系统理解、改写或确认；备选预写标题可保底 | 现有五标题作为作者样例；自由输入是后续功能 | 分析等待不清空草稿；不把改写当新剧情 |
| 22–23 分钟 | 签发：承担表达责任 | 检查归属与断言，返回修改 / 明确签发 / 暂缓 | 现有 confirm 与 publish | 独立按钮，焦点默认在返回；不展示通过率 |
| 23–25 分钟 | 余波：看清自己造成的后果 | 读作者结局，回看刊发时材料；决定是否重玩另一条线 | 五类现有结局；次日录像仅可作为未来补充场景 | 先故事，再可选细节；不以数值成绩取代叙事 |

目标容量：2 位 NPC、1 次互斥调查、3 份证据以内、1 笔可选交易、1 次最终刊发 / 暂缓、5 类结果。拟扩展到 6–9 个有意义的输入动作，不做十几轮同义问答。若真实走查只有 12 分钟，先判断是否缺少比较和表达决策，再考虑补写一段有用内容。

## 4. 沿现有故事组织分支、证据、来源与后果

```text
进入 → 目击者
        ├ 说明用途 / 录音 → 录音 + 已知来源
        ├ 施压 / 录音     → 同一录音 + 来源 + 作者风险事件
        └ 不采用采访     → 无录音、无来源
      → 最后一次调查
        ├ 录像 → 录像 → 编辑台
        ├ 账房 → 请求被拒 / 放弃 → 编辑台
        │       └ 提出 500 → 确认付费 → 账簿 → 编辑台
        │                    └ 拒绝 → 编辑台
        └ 回编辑台
      → 选择标题 ↔ 返回修改
      → 确认签发 → 冻结发布时快照 → 作者结果与事件
        └ 暂缓 → 本版未刊发
```

可视化见 [流程图](screens/00-flow.svg)。该图属于作者规划，不放在玩家界面。

| 路线示例 | 刊发时确实掌握 | 标题 / 归属 | 当前 fixture 结果 | 体验要点 |
| --- | --- | --- | --- | --- |
| 录音 → 录像 | 采访录音、现场录像、目击者来源 | “目击者称安保率先开火” | 归属成立、底层事实有争议；无自动变量增减 | 对来源负责与对事实负责是两回事 |
| 录音 → 录像 | 同上 | “民兵在货场率先开火” | 支持报道；作者事件 Reputation / Public Opinion 各 +1 | 玩家在材料冲突后主动调整表述 |
| 录音 → 账房 → 确认 500 | 录音、账簿、来源 | “Company A 为货场行动提供资金” | 支持报道；Money 600 → 100，刊发事件另计 | 经济代价换来另一种报道，而非全线索通关 |
| 请求账簿被拒 | 只有此前已得材料 | 同一资金标题 | 依据不足报道；作者事件 Reputation -1 | 没拿到的证据不能算作“我知道了” |
| 录音 → 回桌 | 录音、来源 | “安保在货场率先开火” | 现有单目击者临时规则判支持 | 显式保留实验规则争议，不能包装成最终新闻学标准 |
| 任一路线 | 实际拥有的材料 | “城市等待答案” / 暂缓 | 无具体主张 / 暂缓；无自动扣钱 | 允许保守决定，不虚构惩罚逼玩家刊发 |

证据册只列已取得且可阅读的材料。来源 A 的身份和原话只有在录音路径后出现；账房不能回答开火经过，目击者不能回答资金来源。不展示 oracle、关系行编号、评估标签、分支 ID 或规则阈值。结局可以用作者文字说明已发生的后果，签发前不能提前告诉玩家会进入哪类结局。

当前 `later_update` 是作者说明，不等于已实现次日场景。今后如实作“次日录像”，把它作为新增时间点的跟进任务；旧刊发页面保留旧证据，新增材料进入新知识状态，不改旧快照。

## 5. 六屏交互：让工作流形成戏剧

设计板全部标记 **设计提案**。屏幕中的自由输入、确认卡、片段标记和保存状态若尚未出现在试玩中，不得当作已实现。

### S1 采访：人先于面板

左侧是简洁货场剪影和人物位置；中央保留原话与最近两轮交流，底部是输入区。右侧仅一个“随身笔记”入口，证据不常驻铺满画面。人物使用作者角色标识，不绘制未经确认的肖像设定。

自由文本目标版第一轮提示“你想问他什么？”并给三个可改写的意图示例；示例不限制玩家措辞。输入后显示“整理你的问题…”；等待时保留全文，可以取消。先进入 S3 确认执行内容，再由规则选择回应计划，最后显示经过 gate 的 NPC 文字。**当前脚本版**明确标示只有四条示例；同样经 S3 确认后才执行作者分支，不显示虚假的模型等待，也不因尚无解析器而跳过已经实现的确认流程。

### S2 证据册：材料和出处分开读

目录仅含已获得的录音、录像或账簿；正文以“材料原文 / 来自哪里 / 何时取得”组织。已知冲突可以并排看，但不以红绿自动判断可信度。不展示“缺失账簿”灰卡泄露线索。标记原文只是私人笔记，不创建新 Evidence，不改变支持关系。

返回原页面时保留草稿、滚动位置与焦点；文字选择区完整恢复仍待验收。浏览证据不消耗调查次数。双材料对照属于未来提案，默认收起；只有玩家选了两份材料才展开，避免像管理后台。

### S3 语义确认 / 修订：我的话将被怎样执行

显示原句和可读释义：“你准备询问……”“你提到了这份材料”“你的话包含施压 / 指控 / 旁敲侧击”等。实际确认卡必须完整列出候选包含的所有 consequential tactics，不固定最多三条，不把内部 enum 直接给玩家看。

现阶段保留“照此表达”与“返回改写”，不增加第三个同级主动作。字段级修订只是条件性提案：只有后续观察证明返回改写不足以支持玩家表达时，才考虑在**当前可用作者含义**内修改行动、对象、策略和已知证据。所有修订仍经过原 validator，不能直接造状态，也不能用 fixture 答案替模型补漏。系统只说明可观察到的失败或不支持，不能声称已经自动找出任意原句遗漏的关键含义。

完整释义 + 返回改写的最小体验已经实现。是否读懂与是否能发现错误仍是不同问题；按第 1 节的复盘分别记录。该交互不改变 Frozen 的 semantic output 字段；若实际需要改共享权威语义，回到 Master 决策。

### S4 编辑台：一句标题，而非分数仪表盘

中央是大字号标题纸；右侧只展示玩家主动打开的证据摘录。分析后逐条用普通中文解释主张和归属，例如“这句话把开火责任直接写成事实”“这句话引用了目击者的说法”。不显示 evidence sufficiency，不给“可信度 87%”。

编辑任何 consequential 文本后，旧解析失效。草稿留存，只有该版本的完整合法 Claim Set 才能进入 S5。多个主张全部列出，不能只保留第一条；无法解析时保留草稿、让玩家修改或以后重试，不以模板 Claim Set 代替自由标题。

### S5 签发：只在这里真正提交

一张独立签发纸呈现完整标题、归属说明、刊发时已取得的材料清单与中立提醒。材料基础不由玩家当时打开哪一页决定。直接责任断言可提示“这句话将责任写作事实”，不提示“证据不足”。“返回修改”与“确认签发”同屏；焦点初始在返回，不给 Enter 全局发布。无主张标题也可签发。

提交时一次性冻结证据 / 来源 / 主张 / 规则版本，选择作者结果、事件和效果；动画完成与否不能决定是否提交。相同签发操作不得重复扣费或应用后果。交易确认同样独立，清楚显示“支付 500，余款 100”，不以点击报价代替付款。

### S6 结局：先读余波，再看过程

先给刊发标题与作者结局文字，再给“刊发时的材料”和“这次的选择”。如显示四变量变化，用人可读标签与作者事件解释，不显示测试字段。暂缓分支写“本版未刊发”，不能显示印刷成功的画面。

“重新开始”重置整个会话；“回看刊发材料”使用冻结快照。当前试玩若不支持存档，关闭前明确说明进度不保存。后续的再玩邀请应指向不同调查取舍，不奖励把所有结局刷满。

## 6. 视觉与交互规范提案

### 材质、布局与字体

方向名称：**夜班编辑台**。暖灰纸张承载文字，深墨色做桌面与货场轮廓，暗红用于人工标注和最终动作。避免霓虹、玻璃卡片、渐变后台、过多圆角。货场只用轨道、灯架、箱体剪影，给阅读留足空间，不建立尚未确认的地理设定。

| Token | 值 | 使用 |
| --- | --- | --- |
| ink | `#202724` | 正文、剪影、深色按钮 |
| paper | `#F1E8D5` | 主阅读面 |
| sheet | `#FBF5E8` | 正文纸、输入面 |
| muted | `#66675B` | 辅助文字；小字仍需实测对比度 |
| rule | `#C8BCA6` | 分隔线；不作为唯一状态信号 |
| accent | `#8B302B` | 签发、批注、焦点边；不代表真/假 |
| desk | `#28342F` | 环境背景 |

中文标题建议宋体 / SimSun，正文建议 Microsoft YaHei UI；英文标题可用 Georgia。均使用本地后备字体，不下载商业字体。Unity 迁移时需单独确认中文字体许可、打包与字符覆盖，不能把 Windows 系统字体路径当跨平台资产。

1440×900 为设计画布；PC 首轮验收 1280×800 和常见缩放。正文 20–22 px，辅助 16–18 px；标题 38–54 px。正文行宽约 28–38 个汉字，行距约 1.5。间距用 8 / 16 / 24 / 32 / 48；主要按钮至少高 48 px，次要按钮 44 px。尽量一屏有一个主动作，证据册用独立阅读面而非永久三栏。

当前轻量 Tk 窗口允许采用原生 Button / Label / Text 获得键盘焦点和文本阅读能力；Canvas 只画环境装饰。设计稿不是要求本轮重建整套浏览器游戏技术栈。

### 操作和反馈语言

| 情况 | 建议文案 / 行为 |
| --- | --- |
| 正常调查 | “核查现场录像”“去找账房”“回编辑台” |
| 获得材料 | “已收进证据册：采访录音”；附原话，不显示“线索 +1” |
| 交易报价 | “提出 500 的交易”；只有确认按钮才写“支付 500” |
| 理解等待 | “正在整理你的问题…”；草稿始终可见 |
| 模糊输入 | “我还不能确定你要询问哪件事。请改写或选择一个方向。” |
| 标题解析失败 | “这版标题尚未整理完成。文字已保留，可以修改。”；不能签发 |
| 中立风险提醒 | “这句话将责任写成事实。你可以修改，也可以照此刊发。” |
| 取消 | 回到原草稿，取消过期结果的显示；不执行任何游戏行动 |

键盘：Tab / Shift+Tab 遍历，Enter / Space 激活当前按钮；输入内 Enter 换行。当前通过可见按钮“查看系统理解”，不新增发送快捷键。未来若需要 Ctrl+Enter，只能请求理解/分析，不能跳过复核或全局签发。Ctrl+E 可在输入内翻证据，单键 E 在输入内禁用；Esc 返回或收起阅读面。所有功能保留可见按钮，不要求记快捷键。数字键用于后来预写选项，在输入内禁用，按钮旁显示并保留 Tab。

文本支持选择复制和滚动；输入框标明多行方式，中文 IME 组合结束前不触发发送。后续增加 100% / 125% / 150% 字号，避免仅放大背景。当前本地试玩不宣称完整屏幕阅读器支持，后续需真人辅助技术验收。颜色永远配文字 / 图形标记。

必要动效只保留：页面切换 120–180 ms 的纸张淡入、证据入册一次短标记、签发一次落印。全文立即出现，可关闭动效；不逐字打字、不闪烁红灯、不靠声音传达必要信息。模型等待保留静态状态，超过建议 2 秒才增加等待说明；建议 8 秒出现取消 / 返回，具体数值由后续实测调整，不是本轮网络性能承诺。

## 7. 技术迁移：复用内容和边界，不搬整个 Python 运行时

本节保留早期技术责任与后续功能说明；当前迁移输入改用chapter.v1.0而非旧story fixture，具体路径/单一UI/版本与顺序以[制作计划](UNITY_2D_PRODUCTION_PLAN.md)为准。下表旧StorySession条目只作历史参考，不能作为Unity首案生产数据来源。

### NPC grounding、记忆、存档与作者内容何时进入

- **Grounding：保留在迭代 2 的技术后续，不是当前脚本流程的完成前提。** 获准继续时仍只考虑当前两位角色，静态卡、知识边界、动态授权、当前交互与语言上下文分开。目击者不接收账簿内容，账房不接收 oracle。现有 lexical gate 只约束受控命题，不能对任意自然语言宣称无幻觉。作者文本是当前可用基线；技术接入未做，不因显示了作者回应就勾销任务 09，也不为关闭任务而立刻加调用。
- **记忆：迭代 4 才加“本场访谈记录”。** 先存已经执行的作者行为、已显示的授权原话和交易承诺，不让自动摘要变成世界事实；不做跨天长期人格记忆。玩家是否真的重复询问或感到 NPC 失忆，是追加摘要机制的证据。
- **存档：原I4提案延后到Unity首版之后，不先做一套Python存档再重做格式。** 保存章节位置、已获证据 / 来源、作者事件执行记录、草稿、待确认交互、已冻结刊发快照及内容版本。模型候选不能在读取时自动执行；存档不含密钥。不需要现在先造云存档或账号系统。
- **内容组织：迭代 3 将文案、玩家可见证据、规则关系、oracle 分离到可审阅作者层。** 保留现有 fixture 为历史实验输入，不直接覆写它来伪造旧证据。先写两条深度足够的路线，不写内容编辑器。只有作者频繁重复编辑出错时再建工具。
- **Dify：仅在出现可量化的编排问题后评估。** 例如多段调用取消/追踪难以管理，或非程序作者必须改流程；当前直接 adapter 已可满足单一交互，不因路线图上出现名字就部署。

### 成本与等待体验

当前唯一实测路线是已记录的 Groq Free tier 小样本；本规划不做新的价格或供应商比较，不默认免费额度永久不变。下一次实时工作必须另批案例、次数、token、费用上限；任何 key 的存在都不构成批准。

产品建议是“一次明确发送才请求”：输入变化不自动分析，不做 token-count 探针，普通 UI 翻页和证据浏览零请求。对话按一个已发送回合处理，标题只在主动请求分析时处理。只有原合约 runtime / gate failure 可以一次重试，fidelity 观察不触发额外请求。超限或等待取消时，保留草稿和作者离线路径；不悄悄切付费模型。

可预先估算未来一次体验的交互预算：若设计 6 次采访解析、至多 6 次 NPC 表层、2 次标题分析，就是约 14 次首次请求，实际是否合并/减少取决于体验；不能将这个估算当已授权的 14 次调用。若该数量的等待破坏节奏，优先减少无意义回合、使用已授权作者文本，之后才讨论新供应商。

## 11. 首个案件：机制、基本路线、支线与完整闭环

本节保留结构索引；具体文字、节点、目录与结果以[样章设计 v1.0](FIRST_CASE_AUTHOR_DRAFT.md)为准。其第9节政策已在新章独立采用；旧fixture和-Legacy入口继续保留原规则，二者不混装。

### 11.1 案件目标与玩家体验

设计目标：玩家在有限调查时间内形成自己的报道判断，决定如何取得材料、怎样对待消息来源、标题写到什么程度，最后看见这一版报道造成的具体影响。目标时长 20–30 分钟，允许快读和提前结束，不靠强制等待或重复采访填充。

货场事件确定为首案题材。下列时段、人物、材料与分支已审定并装配为本样章，不外推为整个产品 canon。旧 fixture 不改；新版本明确区分作者真相、角色所知和玩家可得材料。

案件的共同主线是“完成这一版报道决定”，并不要求找齐所有材料或刊发唯一正确标题。现场核查与资金追查是两种主线调查方向；支线服务于检验其中的关键问题。重玩价值来自不同的取舍和报道角度，不以集齐全部结局为目标。

### 11.2 基本游戏机制

| 机制 | 玩家具体做什么 | 规则与取舍（提案） | 反馈与边界 |
| --- | --- | --- | --- |
| 采访与追问 | 询问观察范围、追问理由、指出矛盾、请求材料；选择表达方式 | 作者预先定义能回答的问题、合作条件与拒绝结果。语气可影响作者设计的合作后果，但不同语气不必都有额外奖励 | 原句→完整理解→确认/改写→作者结果；确认不证明陈述为真，NPC 不能自行发明承诺或线索 |
| 调查时间分配 | 决定深入一条线，或先接触两条线再挑一条深入 | 采用初始采访后 **3 个调查时段**；基础调查各 1，相关支线各 1。两线都深入需 4，因此本次无法穷尽 | 这是待验证的局部任务资源，不增加第五项全局变量；不使用现实倒计时，读材料/改稿/复核不耗时段 |
| 材料取得与核查 | 阅读录音、影像或账页，检查出处、时间和所能说明的范围 | 材料是否取得、哪些作者关系成立由规则决定；取得一份材料与证明整项指控分开 | 玩家看到原文与出处，不看隐藏支持分。私人笔记不自动生成证据或改判定 |
| 交涉与付款 | 请求、接受已设计交易、拒绝或离开 | 报价不扣款，明确接受才扣款交付；失败与拒绝也有可继续的路线 | Money 在本章先承担真实支付约束；不声称已有完整经济系统。样章采用600/500，不宣称长期经济平衡 |
| 来源关系 | 决定追问力度、如何回应来源顾虑 | 用作者明确的合作/拒绝条件体现，不新增泛化好感度评分。样章采用身份威胁关闭对应合作 | 不把保护来源等承诺偷偷映射到未设计含义；如新增承诺行为需先定义作者可用交互及验证边界 |
| 报道表达 | 选择报道角度、组织主张和出处，决定断言/归属/提问 | 自由标题应完整解析主张；提问或归属都不自动免责。没有材料也允许保守表述或暂缓 | 系统说明语言行为，不透露隐藏支持判断；编辑 consequential 文字使旧候选失效 |
| 刊发与余波 | 明确签发或暂缓，阅读受影响人物和编辑的后续反应 | 签发冻结当时的材料/来源/主张；作者规则决定后果，四变量只经作者事件变化 | 先给具体事件，再可选解释因果和变量；后得材料不改旧快照 |

时段在一次已确认、由确定性规则结算的有效调查结果后消耗。作者安排的拒绝属于结果；模型超时、解析失败、返回改写不结算、不扣时段。进入场景前说明行动成本，场景内普通阅读和措辞调整不逐句收费；未完成的调查不能并行重复领取结果。同一调查完成后，换个问法不重复授予材料或刷新机会。

交涉中的一句“不行”不必立刻结束整场调查；若仍有作者开放的报价或追问，玩家可以继续。只有取得材料、玩家明确离开或作者明确终止合作，才结算这一场的时段。下文“B 遭拒”指最终拒绝结果，不把试探一次误做成不可挽回的按钮陷阱。

三个时段已定为制作基线：允许两线基础调查加一条深入，不能同时完成两条支线。支线分别产出可刊的观察范围与账面用途；不靠加分维持其价值。实际取舍是否成立仍需玩家观察，日后按证据调整版本。

### 11.3 人物怎样支撑机制

| 角色 | 已采用的诉求与冲突 | 对玩法的作用 | 知识边界 |
| --- | --- | --- | --- |
| 目击者 | 希望自己的经历被认真报道，同时担心被公开牵连；坚持最初说法 | 玩家决定只记录结论，还是追问观察位置与可见范围；施压可能使后续核查合作终止 | 只解释自己声称观察到的事情，不能代答资金或获得作者真相 |
| 账房 | 需要权衡交付记录的风险、代价和自己愿意说明的范围 | 请求、交易和账页解释具有不同结果；付款买到材料，不自动买到真实或无限合作 | 只解释接触过的账目，不知道谁先开火，也不能把付款直接解释成指挥关系 |
| 编辑 | 需要在截稿前决定这一版能负责任地讲什么 | 给出任务压力，要求玩家选择报道角度；刊发后回应依据与遗漏 | 不充当全知正确答案提示器；只有当前可知信息，不提前泄露结局 |

这三种角色职能优先服务同一个案件。编辑通过简报与回信出现，不必成为新增自由聊天角色。实际台词、观察局限、交付条件和合作终止已写入作者稿；角色标签只作索引。

### 11.4 基本游戏路线与汇流

完整路线：**任务简报 → 初始采访 → 安排调查 → 基础取证 → 可选深入/换线 → 编辑报道 → 复核与签发/暂缓 → 人物与公共余波 → 回看这一版并结束或重玩。**

| 阶段 | 输入 / 玩家决定 | 输出 / 下一步 |
| --- | --- | --- |
| 任务简报 | 知道事件、刊发任务和调查资源；形成初步关注点 | 明白本案目标，不预告未取得材料；进入目击者采访 |
| 初始采访 | 记录、追问或不采用；没有强制刊发承诺 | 获得授权说法/来源或明确空手结果；进入调查安排，仍可完成案件 |
| A：现场基础核查 | 使用 1 时段检查作者提供的影像材料 | 获得可读影像记录与其公开边界；开启 S-A 或返回调查安排 |
| B：资金基础接触 | 使用 1 时段请求/交涉；必要时确认已设计付款 | 获得账页，或遭拒/放弃且无账页；取得后开启 S-B；均返回调查安排 |
| 深入或换线 | 花剩余时段做相关支线，或去另一基础调查；也可提前回桌 | 形成不同材料组合和未核查事项；时段用尽后进入编辑台 |
| 编辑报道 | 选择本版重点，阅读材料，撰写或重写标题 | 完整可复核的表达候选；不因浏览/改稿扣调查资源 |
| 签发或暂缓 | 理解语言行为后承担刊发责任，或决定本版不刊 | 刊发冻结快照；暂缓形成明确未刊发结果；二者均进入作者余波 |
| 余波与结束 | 看具体人物/编辑/公共反应，回看当时依据 | 本案闭环；允许重玩不同取舍，不自动开启尚未设计的第二天 |

在这个结构中，A/B 是主线分支，S-A/S-B 才是可选支线。一次游玩可以只深入 A，可以只深入 B，也可以两线各接触后挑一条深入。它替代的是旧稿“一次调查二选一”的设计限制；现有程序仍沿旧规则运行。

### 11.5 两条支线必须改变最终判断

| 支线 | 触发与入口 | 玩家行为与代价 | 完成 / 未完成怎样影响报道 |
| --- | --- | --- | --- |
| S-A：核对目击者观察范围 | 初始采访已记录原话，完成 A，且来源仍愿意参与；可见提示说明有一处观察范围值得核对，不提示正确结论 | 使用 1 时段，将影像中的时间/位置与目击者原话对照，确认哪些是亲见、哪些是推断 | 成功获得作者预写的范围澄清，改变可合理表述的范围；拒答则记录未核清，不凭空补证。若合作已关闭，提前显示不可开展，不让玩家支付一个已知无效的入口成本 |
| S-B：核对账页的记录语境 | 已从 B 取得账页，且存在可核对来源/记录 | 使用 1 时段，询问记账对象、时间、记录用途或出处；具体答案由作者写定 | 获得可引用的记录说明，帮助区分“有付款记录”和更强的责任推断；不完成仍可报道已取得材料，但不能自动拥有说明中的新信息 |

两条支线都必须有独立的起因、一次有意义的决策、明确取得或未取得的结果，并汇回编辑报道。它们不奖励“支线完成分”，不保证一定发现反转，也不为核心任务提供唯一通行钥匙。未做支线仍能刊发/暂缓；做了支线应影响依据、措辞、来源关系或具体余波中的至少一项。

作者稿现已明确本案新增细节：目击者的视线曾被货车遮挡，他不是收钱编造；账页真实，用途说明不证明谁下令开火。这些已采用为样章作者内容，已进入独立新章，未覆盖旧程序。背景闲聊可以承担人物塑造功能，但不单独计作有玩法结果的支线。

### 11.6 几条可完成的玩家路径

含支线的路径以满足 11.5 的入口条件为前提；条件不满足时，剩余时段仍可用于其他开放调查或直接回桌。

| 路径 | 调查时段核算 | 玩家得到的体验 | 结束条件 |
| --- | --- | --- | --- |
| 深入现场 | A 1 + S-A 1；余下 1 可去 B 或保留 | 核查开火经过及来源观察边界，主动选择是否分散到资金问题 | 以实际材料写现场报道/归属标题，或暂缓 |
| 深入资金 | B 1 + S-B 1；余下 1 可去 A 或保留 | 为取得材料承担交易代价，再判断账页究竟能说明什么 | 以实际材料写资金报道，或改变报道角度/暂缓 |
| 先广后深 | A 1 + B 1 + S-A 或 S-B 1 | 看到两种报道方向，最后一次机会用于最在意的未解问题 | 选择一个重点或受支持的复合表述；所有主张均完整复核 |
| 取证受阻 | B 遭拒消耗 1；余下 2 可做 A 和可用 S-A | 接受本次接触没有收获，改变调查方案 | 没有账页也能返回编辑台；不伪造材料、不锁死 |
| 提前收束 | 只做初始采访，或任一基础调查后回桌 | 主动承担少调查的信息边界 | 可以合法刊发、无主张表述或暂缓；不把“未查完”自动判为失败 |

两条支线全部完成需 A+B+S-A+S-B 共 4 时段，超过提议预算；不能通过重复进入或重复改写绕过。完整体验不要求走完所有路线，只要求每条可选路线都能回到一个可解释的结束。

### 11.7 刊发后果与完整闭环

结局由本版报道角度、主张及归属、刊发时材料、采访/交易选择共同进入作者规则，不能由模型或一个通用道德分决定。建议用“报道发生了什么 → 涉及的人怎样回应 → 为什么与此前选择有关”的顺序呈现。

| 结果方向（内容提案） | 应给出的具体反馈 | 避免的误读 |
| --- | --- | --- |
| 现场事实报道 | 编辑怎样处理这项判断，来源如何回应自己被引用或被质疑 | 结局不能把当时有依据等同于永恒真相 |
| 资金记录报道 | 公开记录引出什么追问，账房如何回应材料使用，哪些责任仍未证实 | 付款记录不能自动证明组织/指挥了冲突 |
| 有归属但存在争议 | 读者/编辑面对的争议、来源回应，以及后续需要说明的事项 | 有出处不等于无责任；来源说过与底层事实分开 |
| 超出当时材料的断言 | 编辑要求说明、更正或补充的具体内容，以及相关人物反应 | 允许合法冒险表达，不由界面提前泄露 hidden support 或强制改成保守标题 |
| 暂缓 / 无具体主张 | 这一版缺席或未作具体判断意味着什么，哪些问题仍待追查 | 两者分别写作；不能假装已经刊发，也不自动套惩罚公式 |

四变量若变化，必须指明对应的作者事件。采访施压与刊发后果分开解释。作者稿第11节已固定样章事件幅度，第12/13节写明具体余波；声誉按专业跟进/复核事件变化，读者来电不增加公众态度。数值可直接制作，长期平衡仍需试玩。

闭环还包括这些出口：来源拒绝后可换线或回桌；拒绝交易后保留资金且不获得材料；时间耗尽进入写作而非强制签发；玩家暂缓能够结束；解析失败保留原稿且不能冒充成功刊发；退出理解页不产生采访；重玩重置本案状态，玩家上次看到的隐藏材料不自动进入新一局。若自由标题失败后采用预写标题，必须是玩家明确选了另一版作者文本，不能把失败原稿偷偷替换成模板语义。

### 13.1 产品目标与长任务终点

核心体验：在无法查清所有事情的情况下，选择调查方向、决定如何报道，并面对具体人物的回应。一次完整首案应能让玩家记住一个人、理解一次放弃，并在结尾形成重玩时想改变的决定。上述玩家结果由真人观察验证；工程交付不能代替。
