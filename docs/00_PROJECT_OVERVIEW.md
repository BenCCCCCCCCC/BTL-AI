# BTL-AI｜游戏介绍与阶段总览

更新：2026-10-25。本文用于快速理解和对外介绍；实时进度以 [Current State](06_CURRENT_STATE.md) 为准，游戏规则以 [Project Definition](01_PROJECT_DEFINITION.md)、[Decision Log](05_DECISION_LOG.md) 和 [Frozen Contract](08_AI_INTERACTION_CONTRACT.md) 为准。

## 一句话介绍

**这是一款让玩家扮演记者的 AI 辅助叙事游戏：你可以自由输入问题采访角色、调查证据、撰写新闻标题，并承担报道带来的后果。**

## 向别人介绍时可以这样说

> 我在做《Between the Lines: AI Remake》，一款以新闻调查为主题的叙事游戏。玩家不只是点击固定对话选项，而是可以自己输入问题，与角色交流，并决定如何报道事件。AI 负责理解玩家说了什么、让角色自然地回应；事实、证据、剧情分支和关键后果仍由预先设计的游戏规则控制。这样既保留表达自由，也避免 AI 随意编造剧情。目标是先做出一段完整、可玩的 20–30 分钟体验。

这段话描述的是**产品目标**，不是宣称上述体验已经全部实现。

## 游戏独特在哪里

核心不是“任何输入都能变成剧情”，而是“玩家可以自由表达，游戏只执行已设计、可验证的含义”。

新闻标题也不只是填空。把一件事写成“事实”“猜测”或“某人的说法”，会对应不同的报道责任。游戏根据玩家发布时掌握的信息和证据进行判断，不让 AI 充当全知裁判。

产品面向 PC，以 2D 和界面交互为主，背景是虚构的现代国家。剧情是人工设计的分支故事，不是无限生成的世界。

## 现在做到哪里

**已经完成核心规则与设计验证、统一案例执行与逐次记录；三批真实模型小样本完成，D18 多策略单例已通过。现在有按设计v1.0装配的首案脚本可玩样章，仍未接任意文字的AI理解。**

已实现的内容主要是 Python 实验工具：检查模型输出是否合法，处理重试和失败，记录候选与评估，以及限制未经授权的 API 调用。Groq 首轮 5 例共 8 次请求：两例标题一次通过，Dialogue 接口失败、零主张格式失败、NPC 依赖作者兜底。三例复测 3 次请求：零主张和 NPC 成功，Dialogue 仍漏两项策略。最新 D18 v0.3 单例用了 1 次请求，runtime / fidelity 均通过，三项策略和证据正确，无 retry / fallback。三批合计 12 次，授权均已关闭；不能外推任意输入可靠性。

首案样章复用“原句→系统理解→确认或改写→执行”，接通三时段、现场/资金主线、观察范围/账目用途支线、五份完整材料、十二个作者标题、明确刊发或暂缓及具体人物后果。脚本外文字保留但不执行；旧fixture与旧版入口保留。新章26个增量测试通过，并完成原生窗口资金深入/刊发关键路径；没有新模型调用、Unity、存档或真人研究。入口与真实验证见[Handoff](07_HANDOFF.md)。

## 保留的旧短篇（-Legacy）：截稿前的货场

以下一次追加调查/旧支持规则属于此前Experimental验证短篇，继续保留供追溯；当前默认入口为新章。两版都不确定整个产品的正式国家/角色身世或最终剧情。

货场发生冲突，你负责赶晚报。目击者 A 坚持安保先开火；编辑只给你最后一段调查时间。你必须选择核查现场录像，还是追查行动背后的付款记录，然后决定标题如何写。

| 节点 | 玩家选择 | 作者预设的变化 |
| --- | --- | --- |
| 采访目击者 | 说明用途并录音；施压；不采用采访 | 前两者获得同一段原话。施压不会让他说出新的事实，但触发一次暴露风险后果 |
| 追加调查 | 看录像；找账房；立即回编辑台 | 本次只能追加一项调查，开火顺序与资金线形成取舍 |
| 核查录像 | 查看画面 | 获得民兵先开火的录像，与目击者说法冲突 |
| 账房交涉 | 直接请求；提出 500 交易；放弃 | 请求遭拒；已设计的 500 交易需要确认，付款后才取得账簿；其他价码未开放 |
| 撰写标题 | 断言开火责任；归属目击者说法；报道 Company A 资金；写无具体主张的标题；暂缓 | 标题按发布时已经掌握的证据分别评估。发布前可修改，提示不揭示隐藏正确答案 |

五类结局包括：有材料支持的报道、依据不足的报道、来源归属成立但事实有争议的报道、无具体主张、暂缓刊发。数值只是测试占位：初始 Money 600，购账簿 -500，施压 Threat Level +1；已设计的支持报道事件 Reputation / Public Opinion 各 +1，依据不足事件 Reputation -1，其余没有自动变量变化。

两条关键对照：

- **采访 → 看录像 → “目击者称安保先开火”**：录音证明他说过，录像提出相反材料。结局保留“归属成立／事实有争议”的区别。
- **采访 → 账房 → 支付 500 → “Company A 为行动提供资金”**：账簿支持资金报道，但你没有完成开火顺序核查。

作者测试真相仍沿用旧 fixture：民兵先开火、Company A 付款。发布评估不读取这份隐藏答案。例如，只凭录音刊发安保先开火，按 02B 的临时规则可在发布时获得支持；次日出现录像后需要跟进，但原评估快照不能被倒改。该单证人支持规则只是实验，不是正式新闻学政策。

角色语言保持小范围：目击者谨慎、坚持自己的观察；账房正式、担心交出记录。两人不能互相代答自己不知道的事实。当前程序展示的是作者文字；没有让 LLM 决定证据交付、交易或结局。

运行入口和命令见 [Handoff](07_HANDOFF.md)，完整分支数据见 [故事 fixture](../tests/fixtures/railyard_story.experimental.v0.1.json)。下一次产品判断重点是：调查取舍是否清楚、归属与事实的区别能否被理解、报道后果是否合理；尚未进行玩家验证。

## 接下来的路线

最新制作方向已按用户要求收敛为 **Unity 2D＋静态像素场景＋清晰文字界面**。采用一个场景、三张背景、三位角色基础头像与共用阅读/确认界面；先迁移既有v1.0规则，再装配剧情呈现与本局因果回看。设计借鉴分支剧情的关键取舍、延迟回应和章末回看，仍聚焦单案，详见[制作计划](planning/2026-10-25-sol/UNITY_2D_PRODUCTION_PLAN.md)与[作者稿第17节](planning/2026-10-25-sol/FIRST_CASE_AUTHOR_DRAFT.md#chapter-presentation)。下一轮Sol的U0–U2任务已写好，当前未授权执行、未创建工程。

**已有技术与操作底座 → 首案机制/路线/支线设计 → 完整作者稿与结果规则 → 可玩样章 → 玩家体验验证与 20–30 分钟切片打磨。**

首案[样章设计v1.0](planning/2026-10-25-sol/FIRST_CASE_AUTHOR_DRAFT.md)已制作成[脚本可玩版本](../ai/prototype/chapter_desktop.py)，按[DEC-023](05_DECISION_LOG.md#dec-023)独立装配新规则。两条支线分别能写出目击范围与账面用途，刊发后有编辑/来源/公司具体回应；来电不自动增加公众态度。首次读者的取舍、理解和实际时长仍待观察，可用现有样章进行；下一实施批次按新计划先做获授权的Unity离线迁移，不再要求先完成Python存档。[主规划](planning/2026-10-25-sol/ITERATION_PLAN.md#full-case)记录进度，[设计板](planning/2026-10-25-sol/design-board.html)仍是旧提案与历史截图。

完整案件应让玩家形成判断、面对取舍并看到可解释的后果；支线服务于报道，取证失败或暂缓也能够结束。机制和内容可围绕这个目标重设计，范围仍聚焦一个案件，而非一次铺开大型世界与长期系统。

Dify 保留为待验证的编排选择，不是已经完成的功能，也不是必须先搭好才能做游戏的前提。脚本样章已交付，完整切片的玩家验收尚未开始；这份路线说明不自动授权创建 Unity 项目或调用付费模型。

## 回答“目前进度如何”

> 目前处于技术原型阶段。三批共12次模型请求完成了这组样例的定向测量。已有不调用AI的本地图形短故事，支持脚本采访确认、调查、证据、标题与作者后果。首案已经按定稿做成独立脚本可玩样章，主支线、材料、标题和具体后果已接通；Unity 2D迁移及剧情呈现计划已交付，下一轮获明确授权后由Sol做首条可玩路径；首次读者观察仍待做。任意文字理解尚未实现，也没有任意自由文本AI demo或真人验证。

不要写成“已经完成 Dify 工作流、Unity AI demo、玩家验证”或“已经解决 AI 幻觉”。本项目当前的工程测试结果不能证明这些结论。
